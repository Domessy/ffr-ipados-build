A game-isolated build pipeline is prepared in `Domessy/ffr-ipados-build`. Synthetic CI checks the source gateway, setup, transfer and encrypted update inspector. The real source NSPs, keys, actual IPA compilation and iPad launch **remain unverified**.

The local setup additionally expects a nonempty, regular `prod.keys` there (consistent with prior games); if absent, setup fails without running Actions. **Do not upload source game content, keys, tickets or output IPA to public GitHub artifacts.**

## Private on-host design

`bash security/setup_hk.sh` creates only `~/portage-ipados/hollow-knight/`, with `source` pointing to the unique case-insensitive exact game folder directly below Documents. `private/prod.keys` is a protected 0600 copy; mismatching keys are never overwritten. Separate `shader-cache`, `shader-cache-conflicts` and `resultats` are used. No packages, services or system settings are added to CachyOS.

The forced-command SSH gateway in `security/hk_gateway.py` accepts only fixed `hk-*` operations. Local admission requires exactly two **regular** NSP files, each with a PFS0 header; it validates filename hints for title IDs, versions and base/update role. If there are no recognizable filename hints, size-based role inference is accepted only for an unambiguous pair; this is **not** final identity verification. On failure, the setup lists only limited local game filename/size inventory (never keys or raw content) and does not dispatch a build.

`security/hk_transfer.py` transfers the base and update atomically and uses numeric progress in public CI. The runner `security/hk_identify_update.py` compiles the pinned `nx_extract` and invokes `nx_extract.dll` using the working `dotnet` host (avoids the macOS standalone apphost exit-131 issue encountered in the Mina experiment). After decrypting, it strictly verifies base Application title, Patch title and revision **v589824**. It then renames **only the ephemeral runner's update copy** to `[v589824].nsp`. Both original NSPs on CachyOS remain unchanged.

The nxnative build uses a per-title shader CAS with periodic private checkpoints, atomic output return over the fixed SSH route and bounded private logs. No Android SDK or emulation is involved; this is an experimental native iPadOS build.

## Commands on CachyOS, after merging to main

```bash
(
set -euo pipefail
cd "$HOME/portage-ipados/ff-resonance/github-build"
test "$(git branch --show-current)" = main
test -z "$(git status --porcelain)"
git pull --ff-only origin main
bash security/setup_hk.sh
python3 -m unittest -v \
  security/test_cache_import.py \
  security/test_hk_gateway.py \
  security/test_hk_transfer.py \
  security/test_hk_setup.py \
  security/test_hk_identify_update.py
gh workflow run build-hk.yml -R Domessy/ffr-ipados-build --ref main -f mode=build
gh run list -R Domessy/ffr-ipados-build --workflow build-hk.yml --limit 3
)
```

Workflow `.github/workflows/build-hk.yml` supports `preflight`, `keys-check` and `build`. A preflight failure is actionable locally and should **not** lead to repeated full GitHub builds. No source NSPs or keys appear in synthetic CI.

Expected private outputs in `~/portage-ipados/hollow-knight/resultats/`:

- `HollowKnight-nxnative.ipa` only after successful native build;
- `hk-build.log` with full nxnative diagnostics;
- `hk-inspection.log` with bounded private dotnet and encrypted-CNMT inspector errors, even if the build fails before shaders;
- optional `hk-survey.md`, `hk-profile.tsv` when generated by upstream.

For an unsupported version, review the **actual** encrypted CNMT results; do not patch version strings in filenames to force a different unregistered build. On an IPA, test launch, controls (B jump, Y attack, A menu), Unity rendering, save/load, cinematics, and FMOD audio on iPad Pro M5 before marking playable.

## Reversibility

To roll back, remove only the per-game workspace `~/portage-ipados/hollow-knight/` after preserving any required IPA/log/shader cache, and revert the `hk-` gateway dispatch in Git separately when no build is running. The original Documents files and all existing title projects are never changed.
